# 04: AI 批量分类（OpenAI 兼容 HTTP 后端）

**What to build:** 规则和缓存都判不出来的应用，交给模型；**批量问，且不许它发明类别**。

- HTTP 后端：OpenAI 兼容的 `chat/completions`（`base_url` / `model` / `api_key` 从本地配置文件读，key 不进仓库），只用 stdlib `urllib`，不引新依赖。
- 批量：待判项按每批 N 个（默认 20）打包成**一次**请求，要求模型逐项回 `{path, category, confidence}`。
- **枚举校验**：类别必须命中 `categories.json` 的 id；不在枚举里的整条丢弃、计入 `pending`。模型不能创造新类别。
- 降级：超时（默认 10 秒）或 HTTP 失败时，该批全部进 `pending`，不阻塞其它批、不抛未捕获异常。
- 提示词里只放**路径与进程名**，不放窗口标题、用户名或其它可能含隐私的内容。

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] 用本地桩 HTTP 服务端到端跑通：冷启动 N 条 → 断言请求次数 = 批次数量（不是 N 次）
- [ ] 桩返回非法类别时，该条被丢弃并进 `pending`，其余条目正常落缓存
- [ ] 桩超时或返回 500 时进程不崩、该批进 `pending`，统计里能看到失败批次数
- [ ] 断言发出去的提示词字符串里**不含**窗口标题/用户名（隐私回归）
- [ ] 没有配置 `api_key` 时给出可读提示并跳过 AI 阶段（其余流程照常）
